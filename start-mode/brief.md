# 简洁模式 /start/ — 设计 brief

> 2026-10-30 修订：简洁模式 = 精简版控制台，**不是教程**。首页一屏给出 Base URL / API Key / 模型 / 配置片段 / 余额 / 用量；教程只是首页底部的两个可选入口（CLI / 桌面版）。信号线从“教程进度”改为首页顶部的“连接状态条”。

- 用户与任务：不懂 API 的新用户，目标是让 Codex（CLI 或桌面版，Windows）能用起来；之后回来看余额、充值。
- 目标感受：安静、被带着走、最后一步“通了”的瞬间有一点惊喜。
- 核心隐喻：**一条信号线**。你的电脑 ── Yisama ── 模型。每一步是线上的一个站点；完成一步，这段线就亮起。用户在 Codex 里发出第一句话时，一个光点真的从“你的电脑”沿线跑到终点——这就是“检测到第一次请求”的可视化。中转站本来就是一条线，所以这个隐喻是真实的，不是装饰。
- 构图：左侧竖线 + 站点（桌面端固定），右侧是当前步骤的内容；窄屏线变成顶部横向进度。完成后整页变成“使用中心”，线收缩成一条常亮的细线在顶部。
- 色彩/字体：沿用首页 —— 深底 #0a0a10，品牌渐变 magenta→violet→cyan 只用在“通电”的线和关键按钮上；Inter Tight + Noto Sans SC，Key/地址/命令用 JetBrains Mono。
- 关键交互/动效：线的描绘入场；Key 生成时字符解码；复制按钮的勾选；等待时末端站点的声呐脉冲；通电时光点沿线奔跑并依次点亮站点；余额数字滚动；首次选择弹窗两扇“门”随悬停伸缩。
- 避免：统计卡片网格、彩带撒花、大量说明文字、把 token/倍率/分组摆在首屏。
- 第一版范围：模式选择弹窗、接入流程（CLI / Desktop）、使用中心、充值弹窗、设置抽屉、专业模式入口。假数据，`?demo` 显示原型控制条。
